Data Agents: Levels, State of the Art, and Open Problems

👥 Yuyu Luo, Guoliang Li, Ju Fan, Nan Tang 🏛️ HKUST(GZ) / 清华 / 人大 📅 2026.02 · SIGMOD 2026 Tutorial

首次提出 Data Agent 的L0-L5 能力分级 taxonomy，类比自动驾驶 SAE 分级： L0（无自主）→ L1（辅助查询）→ L2（任务级 agent）→ L3（端到端编排，监督下）→ L4（高自主，主动）→ L5（完全自主，生成式）。 用统一框架梳理 data management / preparation / analysis 各方向的代表系统， 并给出 L4-L5 的开放研究问题清单。

1. 动机：术语乱象

❌ "Data Agent" 一词被滥用

当前论文 / 产品中"data agent"用法极不一致 —— 简单的查询助手和"完全自主数据科学家"被混为一谈：

用法 A：查询助手

把 NL → SQL 的 wrapper 称为 data agent，本质上是单步翻译。

用法 B：自主数据科学家

展望中的端到端、能自我探索数据并发现洞察的智能体，目前并不存在。

问题

能力边界模糊 → 用户无法判断系统真实能力；监管者无法定责。

需求

需要一套像自动驾驶 L0-L5 那样的能力分级体系。

✅ 核心贡献

论文（SIGMOD 2026 Tutorial）提出 Data Agent 的L0-L5 分级 taxonomy，并以此组织：① 现有 L0-L2 系统综述；② Proto-L3（端到端工作流自动编排）的前沿系统；③ L4-L5 的开放研究问题。

2. L0-L5 能力分级

L0：无自主

用户写 SQL / 写 pandas，系统只是数据库 / 库本身。Agent 不存在。

L1：辅助查询

NL → 查询的单步翻译（典型 NL2SQL wrapper）。用户提问，Agent 翻译，结果由用户判断。

示例：早期 Vanna / 简单 ChatBI。

L2：任务级 Agent

能完成一个有明确目标的任务（如"做一份 EDA 报告"），需要 plan + 多工具调用，但仍在用户监督下。

示例：Code Interpreter、TaskWeaver、Data Interpreter（典型 L2 / Proto-L3）。

L3：端到端编排（监督下）

能自主编排端到端数据工作流：从理解需求 → 数据获取 → 处理 → 分析 → 报告。仍由人类监督关键决策点。

当前前沿是Proto-L3：部分系统在受控场景接近 L3。

L4：高自主、主动

不仅能完成给定任务，还能主动提出新分析、发现潜在异常、规划长期数据治理。

愿景，目前尚未实现。

L5：完全自主、生成式

有自主目标、自主迭代、自主生成新数据/新方法的能力。

类似自动驾驶 L5：理论上不需要人类介入。

3. 各方向 State-of-the-Art（按 Level 归类）

论文按 data management / preparation / analysis 三类组织。下表为概念性归类参考。

Data Management 方向

  • L1：NL2SQL wrappers (Vanna)
  • L2：DB-GPT、XiYan-SQL pipeline、Agentar-Scale-SQL
  • Proto-L3：能在多 DB 间自主跳转、执行工作流的 agent（雏形）

Data Preparation 方向

  • L1：单功能数据清洗工具 (DataPrep / openrefine)
  • L2：Auto-cleaning agent
  • Proto-L3：端到端 schema mapping + cleaning + validation

Data Analysis 方向

  • L1：单步问答 BI
  • L2：Code Interpreter / Data Interpreter / AgentAda
  • Proto-L3：能主动选方法、组合 skill、生成 insight 报告的 agent

关键观察

  • 大多数已发表系统在 L2 量级
  • 少数研究/产品在 Proto-L3 范围（如 Data Interpreter / 部分 ChatBI）
  • L4-L5 仍是愿景，需要长链推理、自主目标、记忆压缩等突破

4. 关键跃迁（L_n → L_{n+1}）

L1 → L2

关键：从"单步翻译"到"多步 plan + 工具使用"

  • 需要：plan 能力、tool 调用、错误反馈循环
  • 典型工作：Data Interpreter / AgentAda

L2 → L3

关键：端到端工作流的自主编排，跨阶段一致性

  • 需要：长流水线记忆、错误传递控制、可验证性
  • 挑战：跨表、跨数据库、跨工具的状态管理

L3 → L4

关键：从"被动响应"到"主动发起"

  • 需要：自主目标设定、长期记忆、价值对齐
  • 挑战：何时介入用户、不打扰、不越权

5. 启发与开放问题

💡 对从业者的启发

  • 给自家 Data Agent 产品对齐 Level，避免"营销话术 >> 实际能力"
  • 用 Level 来匹配用户期待与系统能力
  • 把"L2 → Proto-L3"作为近期演进目标，比追求 L5 现实

🔬 学术开放问题

  • L3 端到端编排的可验证性如何保证？
  • L4 的"主动性"如何形式化定义？
  • L5 生成式 agent 的安全 / 责任边界？
  • 如何设计跨级别评测？（不能用 Spider 评 L4）

🌍 行业意义

  • 类比自动驾驶 SAE 分级，给 Data Agent 行业一个共同语言
  • 对监管 / 法律 / 责任划分有重要参考
  • 对学界规划研究 roadmap 有指导价值

⚠️ 局限

  • Tutorial 性质，不是定量 benchmark
  • 各 level 之间的边界仍带主观判断
  • L4-L5 描述偏愿景，缺乏可验证标准
