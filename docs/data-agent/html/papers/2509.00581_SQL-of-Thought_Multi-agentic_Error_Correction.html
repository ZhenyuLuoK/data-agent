SQL-of-Thought: Multi-agentic Text-to-SQL with Guided Error Correction

👥 Saumya Chaturvedi, Aman Chadha, Laurent Bindschaedler 🏛️ Amazon / Stanford / MPI-SWS 📅 2025.08

用多 Agent + Chain-of-Thought + 错误分类法引导的纠错解决 Text-to-SQL。 把任务拆为 5 步：schema linking → subproblem identification → query plan generation → SQL generation → guided correction loop。 关键创新：taxonomy-guided dynamic error modification —— 不再依赖纯执行式静态修正， 而是用 in-context learning + 错误分类法引导动态纠错。在 Spider 上达到 SOTA。

1. 核心问题与洞察

❌ 现有 NL2SQL 纠错的两条路径都不够

① 仅依靠 LLM Self-Refine（DIN-SQL 风格）

纯 prompt 让 LLM "自己看再改"，但 LLM 看不到执行结果，无法发现真实错误（列名不存在、类型不匹配）；改起来还经常引入新错。

② 仅依靠静态执行反馈（MAC-SQL Refiner / CHESS）

能拿到执行错误信息，但没有"对错误做分类"的能力。同样的"column does not exist"错误，可能是拼写、列归属错表、JOIN 缺失等不同根因，需要不同修复策略。盲目把错误信息扔回 LLM，修复不稳定。

③ 缺乏 query plan 显式化

直接 NL → SQL 一步生成，把"理解题意 + 选 schema + 设计连接 + 写 SQL"压在一个 prompt 里。LLM 在子步骤间出错难以定位。

④ 缺少"如何思考"的指引

CoT prompting 可以让 LLM 多想一步，但缺少结构化的思考骨架（先想什么、再想什么），效果不稳定。

✅ 核心洞察："把流程显式化为多 Agent + 用错误分类法引导动态纠错"

SQL-of-Thought 把 NL2SQL 拆成 5 个明确的 Agent 阶段，每个阶段有专门 prompt + 专门 ICL 示例。 关键创新在最后的 guided correction loop： 预先建立一个 SQL 错误的taxonomy（例如：schema linking 错、JOIN 错、聚合错、空值处理错、字面值错……）， 当执行出错时，先用 LLM 分类错误属于哪一类，再调用对应 ICL 示例做"有针对性的纠错"， 而不是把错误信息盲扔回 LLM 让其自由发挥。

逻辑链路

NL Question → 🔗 Schema Linking → 🧩 Subproblem Identification → 📋 Query Plan → 🤖 SQL Generation ↺ 📚 Taxonomy-Guided Correction

2. 方法：5-Stage Multi-Agent Pipeline

① Schema Linking Agent

从大 schema 中筛出与问题相关的表/列子集，类似 RSL-SQL / CHESS Schema Selection。

是后续步骤的"必要而精简"输入。

② Subproblem Identification Agent

把复杂问题拆分为可独立思考的子问题，例如：

  • 识别问题中包含的聚合需求 / 过滤条件 / JOIN 需求
  • 明确每个子目标的 schema 依赖

类似 DIN-SQL 的 difficulty/decomposition 思想，但更细致。

③ Query Plan Generation Agent

基于子问题列表，生成结构化查询计划：

  • 需要哪些表与列
  • JOIN 关系与顺序
  • 聚合 / GROUP BY / HAVING
  • 排序 / 限制条件

把"先有 plan 再写 SQL"显式化，类似 CHASE-SQL 的 Query Plan 策略，但作为标准步骤而非可选 prompt 风格。

④ SQL Generation Agent

基于精简 schema + query plan 写 SQL。因为前面已经把"理解题意"与"设计 plan"做完，这一步本质是 plan → 代码 的相对机械化翻译，错误率显著降低。

⑤ Guided Correction Loop（核心创新）

当 SQL 执行错误或结果不符预期时：

  1. 错误分类：用 LLM 把错误归到预定义 taxonomy 的某一类（schema 错 / 聚合错 / JOIN 错 / 字面值错 / NULL 处理错…）
  2. 针对性 ICL：根据错误类别检索对应 ICL 示例（每类有专门的"如何修这种错"示例集）
  3. 动态修正：把错误信息 + 类别 + 针对性示例一起喂回 SQL Generation Agent，得到修正版
  4. 循环直至执行通过或预算耗尽

论文强调："taxonomy-guided dynamic error modification informed by in-context learning" —— 与静态执行反馈形成对比，是该论文的核心差异化贡献。

设计哲学：让"思考过程"显式化（5 个 Agent 各司其职），让"纠错过程"也显式化（错误分类 + 针对性示例）。 这条路线与 SQL-Trail（多轮 RL）形成有意思的对比 —— SQL-Trail 让模型隐式学会交互行为，SQL-of-Thought 把行为模式显式编码进多 Agent + taxonomy。

关键发现

  • Taxonomy-guided 优于纯执行式：错误分类带来更稳定的纠错
  • 显式 query plan 阶段有效：在 SQL generation 前先把 plan 写下来减少错误
  • multi-agent 分工降低单 prompt 复杂度，每个 Agent 只关心一件事
  • guided correction loop对修复"语义对但执行错"的 SQL 特别有效

5. Taxonomy 覆盖的失败模式

基于 SQL-of-Thought 论文的 guided correction loop 设计动机。

列名 / 表归属错

典型错误信息：column "X" does not exist 或 ambiguous column name。

SQL-of-Thought 的处理：

  • 分类为 "Schema Linking Error"；
  • 检索此类专门 ICL 示例（演示如何修拼写、如何指定表前缀、如何重新做 schema linking）；
  • 把示例 + 错误信息 + 候选 schema 重新喂回 SQL Generation Agent。

对比纯执行反馈：盲扔错误信息可能让 LLM 改错列、改坏 SQL。

聚合粒度 / GROUP BY 错

典型错误：column must appear in GROUP BY 或 SQL 执行通过但语义错（漏 GROUP BY 列、聚合错列）。

处理：

  • 分类为 "Aggregation Error"；
  • 对应示例展示如何识别需要聚合的列与分组键；
  • 修正版补齐 GROUP BY / 改聚合函数。

字面值 / NULL 处理错

典型错误：WHERE x = '某值' 但 DB 内字面值大小写或拼写不同；或忘记 IS NOT NULL。

处理：

  • 分类为 "Literal Value Error" / "NULL Handling Error"；
  • 对应示例展示如何用 LIKE、LOWER()、IS NOT NULL 等修复；
  • 对比 CHESS 的 LSH 字面值匹配 —— SQL-of-Thought 在生成时不一定有 LSH，但通过执行 + taxonomy 在纠错阶段解决同类问题。

6. 启发与未来方向

💡 设计哲学

  • 错误也要分类，不能盲修
  • 把"思考过程"显式拆分为 Agent 链
  • Plan-then-write 比 一步到位 更可控
  • ICL 示例可以按错误类别细分库管理

🚀 技术贡献

  • NL2SQL 错误 taxonomy 的工程化构建
  • Guided correction loop 范式
  • 5-stage multi-agent 设计模式
  • NeurIPS 2025 DL4C 工作坊接收

🌍 实践影响

  • 对工业级 NL2SQL 错误分析提供方法论参考
  • 可与 CHESS / MAC-SQL Refiner 集成 —— 用 taxonomy 引导 Refiner
  • 启发后续 PV-SQL 等工作（数据库 probe + rule-based verification）

⚠️ 局限

  • Taxonomy 需要人工策划，覆盖不全时有 fallback 问题
  • 对每类错误维护 ICL 示例库的维护成本不低
  • 论文主要在 Spider 上验证，BIRD / Spider 2.0 等更难 benchmark 上表现需进一步看
  • 多 Agent 链式调用的 token 成本明显高于单步生成
