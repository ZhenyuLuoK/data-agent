AgentAda: Skill-Adaptive Data Analytics for Tailored Insight Discovery

👥 Amirhossein Abaskohi, Amrutha Varshini Ramesh, Issam H. Laradji 等 (9 作者) 🏛️ ServiceNow / UBC / Mila / Polytechnique Montréal 📅 2025.04

首个能"学习并使用新分析技能"的 LLM 数据分析 Agent。区别于固定 EDA / 通用 ChatBI 类工具， AgentAda 维护一个分析技能库（聚类、预测建模、BERT NLP 等）， 自动根据用户目标 + 数据形态匹配最合适的技能。三步骤 pipeline： ① Question Generator（针对用户 persona/goal 生成查询） → ② Hybrid RAG Skill Matcher（从技能库选最佳分析方法） → ③ Code Generator（基于技能文档产出可执行代码）。 Human eval：48.78% 评估者偏好 AgentAda，对比 unskilled agent 27.67%。

1. 核心问题与洞察

❌ 现有 LLM 数据分析工具的局限

① 用户得手动指定方法

典型场景：用户必须自己说"对这份数据做 K-Means 聚类"或"训练随机森林"。如果用户不懂，工具就不会用 —— 把方法选择的负担推给了用户。

② LLM 自带技能集有限

纯 prompt 让 LLM 写 sklearn 代码，对常规 EDA 还行；但涉及 BERT/Transformer NLP、复杂时序模型、专门统计方法时，LLM 本身经验不足，写出来的代码经常错。

③ 通用化 vs 专业化的割裂

已有 Code Interpreter 类工具偏通用（“能跑就行”），但用户期待的是"给我深度洞察"（业务级、领域特异）。

④ 评测范式缺失

现有数据分析 agent benchmark 多关注是否答对单一查询，缺少对"洞察质量（insightfulness）"这种主观但关键的维度的评测。

✅ 核心洞察：用"可扩展技能库"+"RAG 技能匹配"解锁专家方法

AgentAda 把"分析方法"从 LLM 的隐式知识中抽离出来，做成一个显式可检索、可扩展的技能库。 每个技能 = 一段方法文档 + 调用接口 + 适用场景描述。 Hybrid RAG Skill Matcher 根据"用户目标 + 数据形态 + 候选技能描述"做检索 + 重排，自动选最合适的技能； Code Generator 拿到技能文档后产出可执行代码。 这套设计让 AgentAda 能用专家方法（聚类、预测建模、BERT NLP 等），而无需用户懂这些方法。

逻辑链路

用户 goal + persona → ❓ Question Generator → 📚 Hybrid RAG Skill Matcher → 💻 Code Generator → 🎯 Tailored Insights

2. 方法：Skill-Adaptive Three-Stage Pipeline

① Question Generator

输入：用户 persona（角色：营销总监/数据科学家/财务）+ 高层目标（"找出本季度营收异常的客户群"）+ 数据元信息。

输出：结构化查询列表（细化为可分析的子问题）。

关键设计：persona-aware —— 同一份数据对营销总监 vs 财务，应当生成不同侧重的问题。

② Hybrid RAG Skill Matcher

技能库：覆盖聚类、回归 / 分类预测、时序、关联规则、BERT 等 NLP 方法。每条 skill 包含：

  • 名称 + 简要说明
  • 适用条件（数据形态、目标类型）
  • 调用范式 / 关键 API
  • 已知局限性

Hybrid RAG：稀疏检索（BM25 关键词）+ 稠密检索（embedding 相似度）混合排序，避免单一检索方式漏召。

③ Code Generator

给 LLM 注入：用户的细化问题 + 选中的技能文档 + 数据 schema。

LLM 生成：可执行的 Python 代码（pandas + sklearn / transformers / statsmodels 等）。

关键效益：因为 prompt 里有"技能文档"作为强约束，LLM 不再凭直觉乱写，而是按技能文档的范式调用 —— 显著提升专门方法的代码正确率。

④ LLM-as-a-Judge（评测创新）

论文还提出用强 LLM 当 judge，对 insight 质量打分（faithfulness / specificity / actionability）。

论文实证：LLM-judge 评分与人类 evaluator 的偏好高度对齐，可以作为大规模 insight 自动评测的代理。

这条贡献对整个 Data Agent 评测领域有方法论价值。

设计哲学：把"分析方法"这一类知识从 LLM 隐参数中显式化为可检索资产，是 LLM-Tool-Use 思想在数据分析上的落地。skill 可以增量添加，使 Agent 能力随时间增长而非固化。

3. 评估框架：KaggleBench + 人工评估 + LLM Judge

KaggleBench（论文提出的新 benchmark）

  • 从 Kaggle 各领域整理 curated notebook 形成评测集
  • 覆盖多个领域（金融、健康、社交、零售等）
  • 每条样本提供：数据集 + 用户 persona + 高层 goal
  • 评测目标：洞察质量（insight quality），而非"答对一次查询"

评测维度

  • Human evaluation：评估者在 AgentAda vs unskilled agent 输出之间二选一
  • LLM-as-a-judge：自动化打分，与人类偏好对齐
  • Faithfulness（忠于数据）
  • Specificity（领域细致度）
  • Actionability（可行动性）

关键发现

  • 技能库的存在显著提升 insight 质量：人类评估者更倾向 AgentAda 而非无技能版
  • LLM judge 与人类对齐：可以作为大规模评测的可靠代理（论文 alignment 实验）
  • persona-aware 问题生成有效：相同数据对不同角色给出不同侧重的分析
  • Hybrid RAG 优于单一检索：稀疏 + 稠密混合的 skill 检索更稳定

5. 论文展示的代表性场景

基于论文 abstract / introduction 给出的能力定位。

专家方法解锁：聚类

用户给出"找出客户分群"这种高层目标。普通 LLM 可能给出 GroupBy 统计（不够），AgentAda 通过 Skill Matcher 选中 Clustering 技能，按技能文档调用 K-Means / DBSCAN，并自动选择特征列、预处理（标准化）、解读簇。

价值：用户不用懂聚类方法本身，就能用上专家级别的工具。

NLP 分析评论文本

用户问"客户评论的主要情绪与主题是什么"。AgentAda 选中 BERT NLP skill —— 这是普通 LLM 直接写代码容易写错（tokenizer / model card / pipeline 配置）的领域。Skill 文档把正确范式注入 prompt，Code Generator 输出可跑的代码。

论文重点强调：这类"LLM out-of-the-box 不会做"的方法，正是 skill library 的核心价值。

Persona 差异化分析

同一份销售数据：

  • 对"营销总监" → 关注客户画像、转化漏斗、推广 ROI；
  • 对"财务总监" → 关注利润率、坏账风险、现金流；
  • 对"数据科学家" → 关注异常检测、预测建模、特征重要性。

Question Generator 把 persona 作为关键输入，使生成的子问题与最终 insight 高度差异化。

6. 启发与未来方向

💡 设计哲学

  • 方法显式化：把分析方法做成可检索资产
  • persona-aware：洞察的价值依赖角色背景
  • 专业能力可叠加：技能库随时间扩展
  • 评测要看 insight 质量，不是单步对错

🚀 技术贡献

  • Skill-Adaptive Pipeline（首个 skill library 风格的数据分析 Agent）
  • Hybrid RAG Skill Matcher
  • KaggleBench 评测集
  • LLM-as-a-judge 对齐人类偏好的方法

🌍 实践影响

  • 是 LLM 数据分析 agent 综述（2508.02744）中"skill library"路线的代表
  • 对企业 BI 类产品设计直接借鉴：方法库 + 自动选择 = 降低用户门槛
  • LLM-judge 方法可推广到其他主观任务的自动评测

⚠️ 局限

  • 技能库需要人工策划与维护，技能描述质量直接影响 Matcher 效果
  • 当数据规模很大（GB 级）时，单 notebook 风格 Code 执行成本高
  • 对多步骤、跨技能的复杂分析任务，单次 skill matching 不够，可能需要 plan 层
  • 未来：与 Hierarchical Plan（如 Data Interpreter）结合，做成 plan + skill library 的混合形态
