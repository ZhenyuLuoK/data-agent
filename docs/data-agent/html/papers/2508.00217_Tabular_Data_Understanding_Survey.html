Tabular Data Understanding with LLMs: A Survey of Recent Advances and Challenges

👥 Xiaofeng Wu, Alan Ritter, Wei Xu 🏛️ Georgia Tech 📅 2025.07

1. 综述动机

❌ 表格理解的特殊性

① 二维结构 vs 线性文本

表格是二维数据：行表示 record、列表示 attribute、cell 之间存在隐式语义关联。LLM 默认按 token 序列读，容易丢失结构信息。

② 格式高度多样

从规整的关系型数据库表，到带合并单元格的多层级 spreadsheet，再到带说明性文字的 wiki tables。每种格式有不同最佳实践。

③ 任务高度专门化

TableQA、Table Fact Verification、Table-to-Text、Schema Linking、NL2SQL 等任务各有 SOTA 方法，缺乏统一视角。

④ 评测分散

不同 benchmark 使用不同表征 / 不同输入格式，使方法间难以横向比较。

✅ 综述贡献

论文系统性地：① 提出"表格输入表征"的 taxonomy，统一不同序列化方式（Markdown / JSON / HTML / Tuples / 图像 / SQL）；② 把 table understanding 任务按目标聚类整理；③ 指出三大未解决的关键 gap，作为社区研究方向。

2. 表格表征 Taxonomy

文本序列化表征

  • Markdown / Pipe：人类可读，但长表 token 开销大
  • JSON：结构清晰，列名重复带来 token 浪费
  • CSV/TSV：紧凑但语义弱
  • HTML：保留合并单元格 / 样式语义
  • SQL CREATE TABLE + INSERT：DB 视角

结构化 / 增强表征

  • Tuples / Triples：(row, col, value) 三元组
  • 带列描述的 schema（如 XiYan-SQL 的 M-Schema）
  • 带典型值/统计（min/max/distinct 数）
  • 图像表征（MLLM 直接看 spreadsheet 截图）
  • 嵌入表征（TabBERT/TaPas 等结构感知预训练）

表征选择的影响

论文指出表征选择对下游 task 性能影响巨大：

  • 同一个模型 + 同一个 task，换一种表征性能差距可达 10pt+；
  • 没有"通用最优"表征 —— 取决于任务是检索 vs 推理 vs 生成；
  • 对长表/大表，需要先做"表格压缩"（采样 / schema 化）再喂模型。

多表 / 大表挑战

当面对多表 JOIN、TB 级数据、动态变化 schema 时，单一表征不够：

  • 需要多轮交互 / 检索式调用工具；
  • schema linking（如 RSL-SQL / X-SQL）成为关键预处理；
  • 是 NL2SQL / Data Agent 共同面临的问题。

3. 表格理解任务体系

Retrieval / Lookup 类

  • TableQA：单元格定位 + 简单聚合
  • Cell Lookup：找到给定 row/col 的值
  • Schema Linking：把 NL 实体对应到 column/table
  • 多数现有 benchmark 偏向此类

Reasoning 类

  • Numerical Reasoning：跨 row 聚合、比例计算
  • Multi-hop QA：跨表 JOIN + 多步推理
  • Fact Verification：判断声明在表中是否成立
  • Trend Analysis：时间序列分析

Generation 类

  • Table-to-Text：把表格摘要为自然语言
  • NL2SQL：自然语言转 SQL
  • Code Generation over Tables：pandas/sklearn 代码

Modification 类

  • Data Cleaning：缺失值修复、异常修正
  • Schema Mapping：表 schema 对齐
  • Imputation / Augmentation

4. 论文指出的三大关键 Gap

Gap 1: 检索 > 推理

现有 benchmark 多数本质是 lookup：在表里找数。真正考验推理（多步、逻辑、数值）的题占比少。

方向：建造更强调 reasoning 的评测；NL2SQL 中的 BIRD 是一个例子。

Gap 2: 复杂结构难处理

合并单元格、嵌套表头、多 sheet、超长上下文、多表 JOIN 等场景，目前模型表现仍弱。

方向：图像/MLLM 表征 + 显式 schema linking + 工具型 agent。

Gap 3: 跨表征泛化弱

同一模型在 Markdown 训练，换 HTML 测试就掉点。说明现有方法没真正学到"表的本质"。

方向：结构感知预训练 / 多表征联合训练 / 表征不变学习。

5. 启发与未来方向

💡 对 Data Agent 的指导

  • schema 表征是 NL2SQL/Data Agent 的"输入设计"环节，不可忽视
  • 大表必须先做 schema linking，不能全表喂入
  • 多表场景需要 agent 化的多轮工具调用
  • 评测要分清 retrieval vs reasoning

🚀 未来方向

  • 结构感知预训练（保留表二维结构）
  • 面向真实复杂表（spreadsheet、wiki table）的 benchmark
  • MLLM 直接读图像表 vs 文本表的能力对比
  • 跨表征 generalization 的系统性研究
