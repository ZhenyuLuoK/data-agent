1. 综述动机

❌ 现有 LLM agent 综述的不足

① 多数综述偏"通用 Agent"

已有 agent 综述（如 ReAct / AutoGen 类）侧重通用 reasoning + tool use 设计，但 Data Science 工作流有特殊性：长流水线、数据驱动、可验证性强。

② 缺 DS workflow 视角

从 EDA → 特征工程 → 建模 → 评估 → 可视化 → 部署的完整链路，每个阶段对 Agent 能力的诉求不同。

③ 方法对比缺失

Data Interpreter / AgentAda / DS-Agent / TaskWeaver / AutoGen 等系统设计差异在哪？综述需要给出统一坐标系。

④ 评测标准不统一

ML-Benchmark / DABench / KaggleBench / DataSciBench 等评测目标不同，社区缺少 cross-benchmark 视角。

✅ 综述贡献

① 提出"Agent 视角 + DS 视角"双重分析框架；② 综合 review 近年 LLM-based DS Agent 工作；③ 为该方向研究者提供路线图。

2. Agent 视角：四大设计原则

① Roles（角色）

  • 单 Agent vs 多 Agent
  • 角色分工：Planner / Coder / Critic / Executor
  • 典型：MetaGPT 风格的 SOP-based 多角色
  • 设计权衡：粒度过细 → 通信成本大；过粗 → 失去专精

② Execution（执行）

  • Linear ReAct：思考-工具-观察循环
  • Plan-and-Solve：先 plan 后逐步执行
  • Hierarchical Graph（如 Data Interpreter）
  • Tree Search：MCTS/ToT

③ Knowledge（知识）

  • 静态：prompt few-shot
  • 检索：RAG over schema/docs/skill library
  • 微调：领域 SFT（如 DB-GPT-Hub）
  • 经验：experience library（如 Data Interpreter）

④ Reflection（反思）

  • Self-Correction（DIN-SQL 风格）
  • Execution-grounded（CHESS / MAC-SQL Refiner）
  • Critique Agent（专门评估其它 Agent 输出）
  • Verification 节点（断言/统计检查）

3. Data Science 视角：workflow 阶段映射

📥 Data Loading → 🔍 EDA → 🧹 Preprocessing → 🛠️ Feature Eng. → 🤖 Model Dev. → 📊 Eval → 🎨 Vis → 📝 Report

每个阶段对 Agent 的特定诉求

  • EDA：数据状态发现 → 需要 plan 动态调整
  • Preprocessing：处理缺失/异常 → 需要 verification
  • Feature Eng.：领域知识依赖 → 需要 RAG / skill library
  • Modeling：方法选择 → AutoML 或 skill matcher
  • Vis & Report：用户交互 → persona-aware 输出

不同 Agent 的覆盖差异

  • Data Interpreter：全流程 + 动态图
  • AgentAda：偏分析/insight 侧
  • DB-GPT：偏数据库 NL2SQL + GBI
  • AutoGen / TaskWeaver：通用框架，DS 是一类应用

5. 综述指出的开放问题

🔬 技术挑战

  • 长流水线错误传递控制
  • 跨阶段记忆 / 状态管理
  • Reflection 信号的来源（执行 vs LLM judge）
  • 多 Agent 协调成本

🎯 评测挑战

  • 缺少跨 benchmark 统一指标
  • insight 质量主观，需要 LLM-judge 与人类对齐
  • 真实工业场景的 leakage / 数据分布漂移
  • 计算成本评测（token / wall time）

🚀 系统挑战

  • 私有部署 + 数据安全
  • 沙箱执行的安全性
  • 用户协作 / 人在回路设计

🌍 应用方向

  • 面向非技术用户的 Data Agent UI
  • 领域特化 Agent（医疗/金融/制造）
  • 可解释 / 可审计的 DS pipeline
